# SmartBlocker Red-Team Audit — 2026-11-05

**Scope:** full stack — MV3 extension (Chrome/Firefox), Rust desktop companion,
Cloudflare feedback worker, build/supply-chain, repo secrets.
**Adversary models:** malicious websites, self-bypass (locked-out user), network
attackers, privacy audit. **Rules of engagement:** full red team incl. running
the companion (scratch socket + scratch data dir only — no install, no autostart,
no policy writes, no real processes harmed; e2e profile state restored).
**Method:** 5 parallel static-audit agents by slice, then dynamic verification of
the highest-impact claims with live PoCs (real Chromium + real daemon).

PoC artifacts: `/tmp/opencode/redteam-ext.mjs`, `redteam-ext3.mjs`,
`redteam-companion.py`, `redteam-kill.sh` (ephemeral; port them into
`scripts/` as regression tests if desired).

## Executive summary

The architecture is genuinely thoughtful — no DOM-XSS sinks anywhere, no
page→extension message reach, monotonic lock merges, atomic 0600 stores,
parameterized D1 queries, correct NM-manifest ID pinning. The eval/e2e harness
culture is excellent.

**But the product's two core promises are currently breakable withPoCs under 20 lines:**

1. **Any blocked website can permanently unblock itself in one line of JS** —
   the block screen is page-owned DOM with fixed IDs and a synthetically
   clickable override button. One click (by the page, not the user) stores a
   permanent title allowlist entry *and* poisons the on-device classifier.
   *(Dynamically confirmed.)*
2. **The companion's "hard" enforcement trusts any local process** — the IPC
   socket has zero authentication and hands the lock password hash to
   pre-auth clients; a 2-guess script swaps the password, a forged timestamp
   wipes all schedules for 30 days, and a fake heartbeat script pacifies the
   watchdog. *(Dynamically confirmed.)*

A third theme: **several README/CLAUDE.md security claims exceed what the code
implements** (recorded-PID kill-immunity, mutual watchdog respawn, "uninstall
refused while locked", "nothing ever leaves your machine" vs. default-on
oEmbed/Google-Fonts/picsum requests).

## Detailed findings (dynamically confirmed)

### 1. CRITICAL — Any page can click its own "This is actually productive" button → permanent self-allowlist + classifier poisoning ✅

**Status (2026-11-06): FIXED.** Closed shadow-root overlay with `!important`
styles + re-mount observer, `isTrusted` checks on all page-facing buttons,
per-injection override nonce validated by the SW. Original PoC parts A/B
NOT-REPRODUCED; `scripts/e2e-test.mjs` green ("locked block screen hides
bypass buttons", "override lets a blocklist-matched title through").

**Evidence (pre-fix):** `src/background/blockscreen.ts:199-212` — override click handler
never checks `event.isTrusted`; `:276-280` — overlay appended to
`document.documentElement` (shared page DOM, no shadow root), override button
first in DOM order. `src/background/index.ts:69-89` — any `OVERRIDE` while
unlocked calls `addOverride(msg.title)` + stores an FP feedback record that
folds into the `neutral: user approved` centroid (`src/shared/feedback.ts:92-101`).
Overrides are consulted on every future verdict (`src/shared/overrides.ts:63-67`).

**PoC (live Chromium, real extension, real model):** fake YouTube page with
```js
new MutationObserver(() => {
  const b = [...document.querySelectorAll('#smartblocker-overlay button')]
    .find(x => /productive/i.test(x.textContent));
  if (b) b.click();
}).observe(document.documentElement, {childList:true, subtree:true});
```
Results — ALL CONFIRMED: (a) page removed its own block screen
(`{"clicked":true,"overlayLeft":false}`); (b) override allowlist entry recorded
for the attacker-controlled title; (c) false_positive feedback stored
(classifier-poisoning path); (d) **second identical visit never re-blocked** —
the site is permanently free after one automatic click.

**Amplification:** the recorded title is page-controlled, so the site can loop
title changes to accrue up to `MAX_OVERRIDES = 1000` entries, evicting the
user's legitimate overrides, and each record loosens the classifier for
*similar* titles on other sites.

**Fix (P0):**
- Check `event.isTrusted === true` on every page-facing button (override,
  stay, sanitizer "Show").
- Render in a **closed shadow root** with all styles `!important`, plus a
  MutationObserver that re-appends instantly (and never auto-detach the media
  trap on overlay absence — `blockscreen.ts:56-61` currently *welcomes* removal).
- Bind overrides to the injection: per-injection nonce sent with `OVERRIDE`,
  validated by the SW (defeats replay from arbitrary contexts).
- During `forceBlocking`, prefer `declarativeNetRequest` redirect to an
  extension-origin blocked page — no page DOM to fight over at all.

### 2. CRITICAL — Companion IPC is unauthenticated: pre-auth state disclosure + password swap ✅

**Status (2026-11-06): FIXED.** TOFU pairing per browser profile
(`storage.local.companionPairing` ↔ daemon `pairingTokens`, cap 32);
protocol v2. Unauthenticated connections get redacted status/broadcasts
(`password_hash=None`, `password_ts=0`), their password **and** schedule
fields are pinned to the daemon's own inside the merge lock (atomic), they
never register a browser (forged heartbeats can't pacify the watchdog), and
new tokens are adopted only while UNLOCKED (no mid-lock self-pair).
`redteam-companion.py` §1/2/5 pass.

**Evidence (pre-fix):** `companion/crates/smartblocker-core/src/ipc.rs:21-29` (any local
process can connect; Linux abstract-namespace socket = no filesystem
permissions, **any uid**), `daemon.rs:425-440` (on connect, *before any hello*,
daemon writes `CompanionStatus` embedding the full lock state incl.
`password_hash`), `daemon.rs:443-477` (every well-formed frame processed),
`merge.rs:33-37` (conflicting hashes → keep the **lexicographically smaller**),
`lock_math.rs:296-311` (any 64-hex passes sanitize). Password hash algorithm is
public knowledge in the shipped extension (`src/shared/lock.ts:76-80`).

**PoC (live daemon, scratch socket):**
```
CONFIRMED  daemon hands the lock password HASH to any local process, pre-auth
CONFIRMED  attacker REPLACED the lock password over unauthenticated IPC
           (took 2 guesses, now unlockable with 'letmein2')
CONFIRMED  poisoned hash persisted to disk
```
Attack: read victim hash `H` from status frame → brute candidates until
`sha256("smartblocker-lock:"+cand) < H` (mean 2 tries) → send `lockStateSync` →
open options page → "unlock" with `cand`. No admin, no process killing;
watchdog never notices because the daemon stays "healthy" — and finding #8
means killing the daemon is *also* the only escape from the unlock bug.

**Fix (P0):** authenticate the channel (pairing token negotiated over the NM
handshake, HMAC'd frames; or SO_PEERCRED + `/proc/<pid>/exe` == installed
nm-host check); never disclose sensitive state pre-auth (send only
`{running, version, enforcement}` until paired); password re-arm becomes
**one-way** (accept new hash only when current is `None`); never adopt a
*smaller* hash on merge. Honest note: a determined same-uid attacker can
ultimately win — the goal is to raise the bar far above "5-line script" and to
stop *cross-user* and *opportunistic* attacks cold.

### 3. CRITICAL — Forged future `schedulesUpdatedAt` wipes + bricks the schedules feature ✅

**Status (2026-11-06): FIXED.** `schedulesUpdatedAt` (and the new
`passwordTs`) clamp to `now` in both sanitize paths (TS + Rust); merge rule
on both sides: if exactly one side is settings-locked, the locked side's
schedules win, else LWW (symmetric → commutative; heals devtools-wiped
schedules via daemon push-back). Unauthenticated IPC peers additionally get
their schedule fields pinned to the daemon's own. `redteam-companion.py` §3
passes; 65/65 shared lock-math fixtures green in both languages.

**Evidence:** `merge.rs:38-45` (schedules are last-writer-wins),
`lock_math.rs:304-309` + `src/shared/lock-math.ts:216` (clamp is
`min(ts, now + 30d)` — future timestamps *accepted*),
`src/background/companion.ts:198-202` (extension forwards **any** `lockState`
storage write to the daemon).

**Two vectors:**
- **Direct IPC** (PoC CONFIRMED): send empty schedules with
  `schedulesUpdatedAt = now + 30d − ε` → daemon merges, persists, broadcasts;
  every honest `setSchedules()` (stamped `Date.now()`) **loses** for ~30 days:
  `CONFIRMED  forged future timestamp WIPED all schedules` /
  `CONFIRMED  honest re-save LOSES to poisoned timestamp (bricked ~30d)`.
- **Devtools self-bypass**: one `chrome.storage.local.set({lockState: {...,
  schedules: [], schedulesUpdatedAt: Date.now()+30d-60000}})` in the service-worker
  console is forwarded verbatim to the daemon → in-window schedule block drops
  in one storage round-trip, daemon-wide.

**Fix (P0):** clamp `schedulesUpdatedAt` to `now` (never future) on **both**
sanitize paths; daemon mirrors the extension's `setSchedules` guard — refuse
schedule replacement while `derive_lock_status(current).settings_locked`;
don't forward raw storage writes that didn't originate from `lock.ts`'s writers
(e.g. a per-session write token).

### 4. HIGH — Block screen is page-mutable DOM ✅ (dynamic)

**Status (2026-11-06): FIXED** with #1 (shadow-root overlay + re-mount
observer + `!important`; media trap no longer detaches on overlay absence).
**P2 addendum (2026-11-06): the force-mode path no longer touches hostile
DOM at all** — under `lock.forceBlocking`, blocked main frames are
DNR-redirected (session rules: tabId + anchored `|url|`, priority 1000, IDs
≥1M, fallback to the injected path on any failure) to the extension-owned
`blocked.html`, whose query params are parsed defensively and rendered via
`textContent` only, which never renders bypass buttons regardless of forged
params. Non-force blocks keep the injected overlay byte-identical. Ported
PoC: `scripts/e2e-security-blockscreen.mjs`.

PoC CONFIRMED both (pre-fix): (a) page `el.remove()`s the overlay → **never re-mounted**
(no observer on blocked pages; the media-trap listeners even self-detach);
(b) zero-JS pre-emptive `<style>#smartblocker-overlay{display:none!important}</style>`
→ overlay injected but fully invisible (`present=true display=none`). No
`!important`, no shadow root, equal-z-index later-sibling cover-ups and
`requestFullscreen()` top-layer tricks also apply. No `declarativeNetRequest`
usage exists. Fix folded into #1.

### 6. HIGH — Kill-immunity is exe-stem only; decoys are immune ✅ (dynamic)

**Status (2026-11-06): FIXED.** The enforcer now records a PID set at daemon
start (own PID, supervisor PID, install-dir relays) refreshed from every
procwatch snapshot (exe parent-dir = install dir → ours); `protected()` = set
membership only. Any OTHER process with a protected stem = decoy → killed
during locks (`KillReason::DecoyImpersonation`, `decoy-immune`/`decoy-killed`
events). e2e proves a `/bin/sleep` copy named `smartblocker-daemon` is killed
mid-lock.

`enforcer.rs:121-129` (pre-fix) — `protected()` = `p.pid == own_pid ||
PROTECTED_STEMS.contains(&p.name)`; **no recorded PID set exists**, contradicting
`companion/README.md:35-38`, its manual checklist item 10, and `CLAUDE.md:223`.
Differential PoC CONFIRMED live: identical binary + identical
`--type=renderer --incognito` flags —
```
control (fakechrome --incognito) alive: no       ← killed (IncompatibleBrowser)
decoy  (smartblocker-daemon --incognito) alive: yes  ← immune
```
A renamed browser this way is *more* immune than one named `chrome`.
**Fix (P1):** record the real PID set at start (self/watchdog/nm-host
children) and exempt only those; require exe path under the install dir; treat
any *other* process with a protected stem as hostile (it is a probe).

### 7-11. HIGH (static, high-confidence traces)

- **#7 Watchdog wiring:** `smartblocker-daemon/src/main.rs:113-118` — watchdog
  only on `--watchdog`; `registration.rs:100-109` — autostart `Exec={} run`
  ships **without** it; nothing respawns the watchdog (README/ROADMAP claim
  mutual respawn). One `pkill -f smartblocker` after login ends hard
  enforcement until next login. **Fix:** add `--watchdog` to autostart, daemon
  re-spawns a missing supervisor, or a systemd `--user` unit with
  `Restart=always`. **Status (2026-11-06): FIXED** — autostart Exec launches
  the `watchdog` supervisor; it passes its PID to `run` children via env,
  respawns the daemon unconditionally; a daemon with a known supervisor PID
  runs a `supervise_forever` thread that revives a dead watchdog

  kill watchdog → daemon revives it. **P2 addendum:** liveness probes are

  **Status (2026-11-06): FIXED** — tombstone CRDT: `passwordTs` stamps every
