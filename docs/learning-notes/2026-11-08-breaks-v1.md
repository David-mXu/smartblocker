# Breaks v1: delay and random-text gates

## Problem and scope

Phase 5 Batch 2 item 5 needed temporary relief from SmartBlocker's classifier
without becoming a way to shorten an existing lock. Two gates were required:
a configurable delay and typing freshly generated random text. Break settings
must be fixed while locked, and an incorrect proof must not write lock state.

The central concept is **orthogonal state**. A break is an additional interval
stored next to the lock sources, not a mutation of those sources. Its only
runtime effect is to relax a successful classifier's block verdict.

## Schema and state machine

[`LockState`](../../src/shared/lock-math.ts) adds four serialized fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `breakStartedAt` | `number \| null` | Request time, not necessarily activation time |
| `breakNotBefore` | `number \| null` | Delayed activation; `null` means immediate |
| `breakEndsAt` | `number \| null` | Exclusive classifier re-block boundary |
| `breakUpdatedAt` | `number` (omitted legacy value reads as `0`) | Stamp for the entire break operation |

The three interval fields are one operation; they are not independent maxima.
Status derives `breakActive` from wall time only. Activation is inclusive and
the end is exclusive: `activation <= now < breakEndsAt`. Pending breaks are not
active. Invalid, partial, reversed, non-finite, and overlong intervals become
an inert all-null tombstone. Request stamps are capped at `now`; activation and
end timestamps are capped at `now + 24h`.

| State | Entry condition | Classifier verdict | Lock fields |
| --- | --- | --- | --- |
| None | No live interval | Unchanged | Unchanged |
| Pending | Valid operation, `now < activation` | Unchanged | Unchanged |
| Active | `activation <= now < breakEndsAt` | Relax successful classifier blocks | Unchanged |
| Ended | `now >= breakEndsAt` | Unchanged | Unchanged |
| Cancelled | Fresh all-null operation and stamp | Unchanged | Unchanged |

`startBreak` permits only a locked state with no pending/active operation.
`cancelBreak` creates a fresh tombstone. Those are the only new transitions,
and both live in [`lock.ts`](../../src/shared/lock.ts); the background gate and
popup never construct lock writes themselves. Existing lock operations remain
unchanged. The settings service refuses break-configuration writes whenever
any lock source is active, while the background gate reads the locked settings
when starting a break.

### Pure helpers and edge decisions

There is one already source-only, pure break module
([`shared/breaks.ts`](../../src/shared/breaks.ts)), rather than splitting the
very small clamp/proof API across three bodies. It contains no browser/storage
imports, storage state, module-level stateful class, timer, or long-lived
object, so additional refactoring would add complexity without isolating any
remaining responsibility. The larger interval/merge functions remain in
`lock-math.ts`, which was already the shared pure lock module.

Clamps are delay `0–60` minutes (default `1`), duration `1–1440` minutes
(default `10`), and proof length `10–1000` symbols (default `100`). Break mode
is `off`, `delay`, or `random-text`. The delay and duration share a 24-hour
construction horizon. Random generation uses `crypto.getRandomValues`, 32
unambiguous uppercase symbols, and groups of five. Every byte maps to one
symbol without modulo bias because `256 % 32 == 0`. Spaces and input case are
presentational; other symbol mismatches fail. A challenge lives only in the
service worker for at most 15 minutes. Requesting a new one replaces the old;
successful use consumes it; replay or a sleeping service worker invalidates
it.

## Investigation and implementation

1. **Mapped existing lock ownership first.** `lock.ts` already owned legal
   transitions, while `lock-math.ts` supplied pure derivations and the Rust
   companion mirrored them. The implementation therefore added break changes
   to those layers instead of letting popup messages patch storage. The
   storage test uses direct Node type stripping, `module.registerHooks` for
   extensionless TS imports, and a `chrome.storage` mock to count real writes.
2. **Made break state merge as one LWW operation.** Independent maxima would
   combine timestamps from different operations and could manufacture a long
   unintended break. A cancellation tombstone gives a newer cancellation
   authority over a stale peer's active interval. Both languages consume the
   same golden fixtures, including same-stamp conflicts.
3. **Made wall time authoritative.** MV3 alarms wake the worker but do not
   define truth. `nextBoundary` includes delayed activation and re-block;
   boot, lock writes, and boundary alarms rebuild the next alarm and sweep
   eligible tabs. A dead worker cannot leave a break logically active past
   its end because every status read derives again from timestamps.
4. **Placed relaxation after verdict production.** Successful model verdicts
   in sub-item, sub-frame, and main-frame paths are relaxed only after the
   existing override/channel handling. Deterministic URL/title/channel rules,
   deterministic embed/adult rules, and fail-closed unavailable-classifier
   results keep their existing decisions. `forceBlocking` and all daemon
   enforcement remain unchanged. The initial item 5 pass did not edit the Rust
   daemon/enforcer; `store.rs` had only a compile-compatible struct default. A
   later post-merge audit added authentication-only operation-field pinning in
   `daemon.rs`, documented in
   [`2026-11-08-companion-operation-auth-pinning.md`](2026-11-08-companion-operation-auth-pinning.md).
5. **Added the two surfaces.** The popup owns display/input only; the service
   worker generates and verifies random text. Options controls describe the
   active lock and are disabled while locked. All new primary DOM ids are
   registered in [`design-notes.md`](../design-notes.md) §7.

## Merge contract

| Condition, in priority order | Winner |
| --- | --- |
| Different `breakUpdatedAt` | Newer operation |
| Same stamp, one all-null tombstone | Cancellation |
| Same stamp, different `breakEndsAt` | Earlier re-block |
| Same stamp, different `breakNotBefore` | Later activation |
| Same stamp, different `breakStartedAt` | Later request |

This ordering is total and argument-order independent. Timer/frozen maxima,
password CRDT behavior, schedule LWW/union behavior, and lock-reason ordering
are unchanged. Sanitization uses only the requested interval, not individual
fields from separate candidates.

## Tradeoffs and residual risks

- **Equal-millisecond operations.** The LWW stamp has millisecond resolution.
  The fail-closed tie list resolves conflicts deterministically, but a newer
  cancellation in the same millisecond cannot be distinguished from a stale
  one; cancellation deliberately wins. Two legitimate break starts in one
  millisecond may pick the shorter break, favoring re-block over relaxation.
- **Clock behavior.** Breaks deliberately use wall time. The existing
  anti-clock-tamper code compensates timer/frozen deadlines, not break
  timestamps. Moving the wall clock can therefore end a break early or keep
  it pending/active longer; this does not shorten the underlying lock. Peer
  clocks and heartbeat delivery times can also affect which LWW operation is
  newest. No convergence protocol can infer intent without a trusted clock.
- **Redirects already displayed.** Existing force-redirect session rules can
  originate from classifier, deterministic, or fail-closed verdicts. Their
  recovered metadata does not persist enough provenance to release exactly
  the classifier subset after a service-worker restart, and the open-tab
  sweep intentionally skips extension-owned pages. Consequently an already
  redirected tab is not retroactively navigated away from `blocked.html` at
  break start; subsequent eligible classification is relaxed. Clearing all
  rules would incorrectly weaken deterministic/fail-closed enforcement, so it
  is intentionally not used.
- **Rust compatibility.** Additive serde defaults let old JSON load. Older
  peers that ignore the new fields will not relax their own verdicts, which is
  fail-closed but means mixed-version relaxation is not synchronized.
- **Scope remains finite.** This implementation does not prove version-vector
  causality, malicious-companion causality, or browser UI behavior. It proves
  the documented commutative/idempotent LWW cases and wall-time math through
  focused tests.
